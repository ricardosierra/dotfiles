# Git Hooks Globais Anti-Autoria de IA

Os dotfiles vêm por padrão com proteção global instalada contra co-autoria e trailers forçados de agentes de IA (como Cursor, Claude, Grok, Codex, OpenAI, Gemini, Copilot, etc.).

---

## Como funciona

Ao instalar os dotfiles (`dotfiles install` ou `init/15_git.sh`), o Git é configurado globalmente com:
* `core.hooksPath = ~/.git_hooks`
* `init.templateDir = ~/.git_template`
* `~/.config/husky/init.sh` (para projetos que utilizam Husky)

### As 3 Camadas de Proteção

1. **`pre-commit` (Validação de Identidade)**:
   Impede que qualquer processo defina `GIT_AUTHOR_NAME` ou `GIT_AUTHOR_EMAIL` como sendo de um agente ou modelo de IA. O autor deve ser sempre o desenvolvedor real.

2. **`commit-msg` (Sanitização Automática)**:
   Antes de calcular o SHA do commit, inspeciona a mensagem e remove automaticamente qualquer linha como:
   * `Co-authored-by: Cursor <cursoragent@cursor.com>`
   * `Co-authored-by: Claude <noreply@anthropic.com>`
   * `Co-authored-by: Grok <grok@x.ai>`
   * `Made with [Cursor](...)`
   * Menções e badges de IA (`Generated by ...`, etc.)

   *Nota*: utiliza `clean_commit_msg.py` (Python 3) com fallback automático para pipeline POSIX `grep`/`sed` caso o Python não esteja presente no sistema.

3. **`pre-push` (Bloqueio de Envio)**:
   Antes de enviar os commits para o GitHub/GitLab, inspeciona o intervalo de commits sendo enviados. Se algum commit contiver créditos ou trailers de IA, o push é abortado com aviso.

## Suporte Multiplataforma

* **macOS**: Ativado automaticamente via `dotfiles install`.
* **Linux (Ubuntu, Debian, Fedora, Arch, etc.)**: Ativado automaticamente via `dotfiles install`.
* **Windows (Git Bash / MSYS / WSL)**: Ativado automaticamente via `dotfiles install`.
* **Windows (PowerShell)**: Pode ser instalado/atualizado diretamente executando:
  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts\install_git_hooks.ps1
  ```

---

## Compatibilidade com Repositórios Existentes

* **Hooks locais**: Se um repositório possuir seus próprios hooks em `.git/hooks/`, nossos hooks globais delegam a execução para o hook local, preservando lints e testes pré-existentes.
* **Husky**: Repositórios que usam Husky (v7+) executam `~/.config/husky/init.sh` automaticamente antes dos hooks do projeto, garantindo proteção sem precisar alterar arquivos versionados no repositório.
